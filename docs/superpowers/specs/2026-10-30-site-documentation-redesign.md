# Zt UI 文档与演示站重建设计

状态：已批准。

## 1. 目标

重新建设面向 Vue 开发者的 Zt UI 官方文档站。开发者能够快速找到组件、了解使用场景、操作真实示例、复制完整代码，并核对准确的 API。

参考 Element Plus 的分类导航和连续阅读体验，以及 Ant Design 的场景说明、示例组织和接口呈现。采用 Zt UI 自有品牌、中文内容及真实组件效果。

本次重建包括全新的站点布局、导航、搜索、页面内容模型、示例、API 提取和展示、测试及 Pages 构建。旧站作为删除对象，不作为新版代码和内容模板。

组件库 `src/` 的功能、API 和样式保持现有契约，包括 VTableGrid。站点缺陷在站点中解决；若发现组件本身的问题，单独定位和报告。

参考页面：

- https://element-plus.org/zh-CN/component/button.html
- https://element-plus.org/zh-CN/guide/design.html
- https://ant.design/components/button-cn/

## 2. 方向比较

| 方向 | 特点 | 适用性 |
| --- | --- | --- |
| Ant Design 式双列示例 | 适合短小、相互独立的演示，页面紧凑 | 表格、表单、长列表及复杂浮层需要较宽空间，不宜全站统一双列 |
| Element Plus 式单列文档 | 顺序阅读，说明、示例、API 连续，复杂组件有充足宽度 | 适合 Zt UI 的业务组件和 Vue 单文件示例 |
| 本设计推荐的组合 | 单列文档为主体，加入明确场景说明、统一示例容器和细分 API | 保持统一阅读路径，兼顾复杂组件和简单组件 |

建议采用第三种。简单组件可以在同一示例内部并排展示若干效果，示例卡片本身仍按阅读顺序纵向排列。

## 3. 信息架构

顶部主导航提供「指南」「组件」「扩展」，另提供版本、GitHub、搜索与尺寸、圆角、主题直接控件。站点默认中文，保留组件英文名称和真实英文 API 标识；本轮不新增全站英文翻译。

### 首页

- 简洁介绍：Zt UI 的用途、Vue 3 与 TypeScript 定位。
- 「快速开始」「浏览组件」两个主要入口。
- 一组可实际操作的小型业务示例，展示输入、选择、按钮、表格及反馈的组合；不依赖后端。
- 常用组件入口与安装命令。
- 不展示开发计划、未实现组件或实施进度。

### 指南

- 安装：依赖、样式、包管理器命令。
- 快速开始：最小可运行 Vue 示例，按需导入方式。
- 全局配置：尺寸、主题、圆角等实际支持的配置与优先级。
- 暗色模式和样式定制：站点主题与组件预览主题的关系。
- TypeScript：组件公共类型、实例方法及泛型使用示例。
- VTableGrid 接入：必要的 VisActor 依赖、普通入口与 Canvas 子入口、样式与懒加载边界。
- 更新日志：展示现有版本发布事实，不混入开发记录。

### 组件

左侧按基础、布局、表单、数据展示、导航、反馈、浮层、媒体分类。条目使用「Button 按钮」形式，分组与排序固定。

提供组件总览，支持关键词筛选和分类跳转。公开导出的子组件可以归属父组件文档，例如 FormItem、TableColumn、VTableGridImportDialog，但必须在文档覆盖清单中有明确归属和页内锚点。图标集中在 Icon 图标库页面。

覆盖范围以当前公共导出与源码清单为准，不将旧站的 79 个页面或 383 个示例数量作为设计目标。

### 桌面

- 内容最大布局宽度约 1440px；左侧导航约 240px，右侧目录约 200px，正文以 760–880px 阅读宽度为主。
- 顶部固定；左右导航可在自身范围内滚动，正文使用浏览器原生页面滚动，避免多层正文滚动。
- 约 1200px 以下隐藏右侧目录；约 960px 以下左侧切换为抽屉；移动端正文单列。
- 表格和 API 容器可以内部横向滚动，不导致页面整体溢出。示例需要最小宽度时明确给出内部滚动区域。

### 视觉语言

站点采用清晰、克制的文档风格。纯色背景、细分隔线、少量强调色、小圆角；示例区域真实呈现 Zt UI 的组件视觉。

| 角色 | 浅色建议 | 暗色建议 |
| --- | --- | --- |
| 页面背景 | `#ffffff` | `#141414` |
| 次级背景 | `#f6f7f9` | `#1d1e1f` |
| 主文本 | `#1f2329` | `#e5e7eb` |
| 次级文本 | `#60656f` | `#a3a8b3` |
| 分隔线 | `#e5e7eb` | `#34363b` |
| 品牌强调 | `#1677ff` | `#69a7ff` |

字体使用本地系统中英文字体，代码使用本地等宽字体，不加载外部字体服务。正文约 15px，行高约 1.75；页面标题约 32px，节标题约 24px，代码约 13px。

本轮不采用旧站的大面积毛玻璃和悬浮主题控制条。size、borderRadius 和 theme 通过顶部的直接控件统一设置；不添加全局语义状态切换。站点导航、正文和代码区使用固定的文档阅读尺寸。

## 5. 组件文档结构

每个组件页按照以下顺序组织：

1. 英文名称与中文名称、一句话功能说明。
2. 使用场景：解决什么问题，重要使用限制。
3. 基础用法：最短但完整的可运行示例。
4. 常见功能：围绕具体属性、事件、插槽或状态说明。
5. 复杂场景：仅在组件确有需要时提供。
6. API：按实际组件拆分 Props、Events、Slots、Exposes 与必要类型说明。
7. 相关组件、上一页和下一页。

不机械要求每个组件展示相同数量的示例。简单组件覆盖核心用法和关键变化；复杂组件完整覆盖主要能力，不能只有一个通用占位示例。

重要组件覆盖要求：

- Button：语义状态、尺寸、形状、禁用、加载、自定义内容和原生按钮行为。
- 表单与输入：双向绑定、校验、禁用/只读、清空、插槽、尺寸、事件和表单联动。
- 选择类：选项结构、单选/多选、筛选、受控值、异步行为及空状态，以实际 API 为准。
- 日期与时间：支持的类型、范围、禁用规则、值类型及格式；不展示组件未实现的模式。
- Table、Tree 等：字段结构、选择、排序、展开、插槽、分页及关键边界。
- Modal、Drawer、Popover 等：打开/关闭、异步忙碌态、关闭拦截、嵌套交互及内容定制。
- Upload：选择/拖拽、校验、状态、自定义请求与失败重试；联网请求使用本地模拟，业务接入示例明确需要调用方接口。
- 命令式反馈：展示实际公开入口，持续消息、更新、关闭和异步确认等能力；依赖与样式导入说明准确。
- VTableGrid：本地/远程分页、本地全量、配置式表单和字典、草稿新增/修改/删除、保存与撤销、汇总、冻结、列设置、筛选、操作/右键、Canvas 内容、导入/导出及生命周期。远程数据用本地异步模拟服务。

## 6. 示例容器与源码

每个示例由独立 `.vue` 文件提供运行结果与原始源码。页面说明独立维护，不从渲染后的 DOM 反向拼装示例代码。

示例容器包含：

- 清晰的标题与必要说明。
- 可操作的真实组件区域。
- 统一底部操作栏：展开/收起源码、复制完整源码、重置示例。
- 代码展开后保持语法高亮和横向滚动；复制得到可直接用于业务项目的完整单文件组件。
- 复制成功/失败有明确反馈；不依赖成功权限假设。
- 重置重新创建当前示例，恢复本地交互状态，清除它创建的反馈或浮层，不能重置其他示例。

复杂组件可以局部提供业务参数控件，但不另外建立独立的 size、borderRadius 或 theme 设置。专门说明尺寸、嵌套配置及属性优先级的示例可以显式覆盖，并明确标注。语义状态、校验状态与业务状态各自通过真实组件 API 展示，不添加全局统一状态注入。

示例不依赖站点专属状态、未展示的工具函数或其他示例文件。辅助数据和模拟服务放在可复制代码中；必须额外安装的依赖明确标注。组件样式在快速开始中说明，特殊子入口样式在对应页说明。

### 全局 size、borderRadius 与 theme

顶部直接提供显示 mini/small/default/medium/large 原始属性值的 ZtSelect 尺寸下拉框、0–24px 连续圆角 Slider 及太阳/月亮主题双态按钮，桌面同排，移动端使用第二行紧凑工具栏，不使用设置弹窗或数值输入。设置作用于首页示例、全部组件页及其预览浮层，切换页面后保留。

| 设置 | 取值 | 初始值 |
| --- | --- | --- |
| size | mini、small、default、medium、large | default |
| borderRadius | 非负像素数，界面提供 0–24px 数字输入 | 11px |
| theme | light、dark | 无已保存偏好时跟随系统 |

- 通过应用级 `ZtConfigProvider` 传入三项设置，使用组件库实际的继承机制；不通过站点 CSS 强制改写组件尺寸或圆角。
- 显式属性和嵌套 Provider 保持组件库自身优先级。尺寸/圆角固定或不支持相关配置的组件按实际契约展示，不伪造能力。
- 文档外壳随全局 theme 切换明暗配色；size 和 borderRadius 统一控制真实组件，导航、正文、代码与 API 表格保持稳定阅读布局。
- 全局设置保存到本地，刷新后恢复；只接受合法取值，失效存储回退默认值。首次采用系统主题，手动选择后优先使用手动偏好。
- 默认值为 default、11px 和跟随系统的主题策略。跟随系统是站点偏好策略，向 Provider 传入的 theme 始终为 light 或 dark。
- 源码区和复制内容都经过 Prettier 完整格式化，包含 template 缩进、脚本与样式；源码区显示当前全局 Provider 配置；「复制完整示例」包含必要的 Provider 导入及当前配置，形成独立可运行的 Vue 单文件组件，不引用站点私有状态。
- 设置变化不重置示例业务数据、清空编辑草稿或关闭正在操作的组件浮层。Teleport 内容也应正确呈现当前主题与圆角。
- 示例的「重置」只重置当前示例业务状态，不改变全局外观设置。

## 7. API 文档与源码契约

旧站生成器、元数据、覆盖表和页面壳整体替换。新版建立独立的数据模型与提取流程，公共组件源码和导出类型作为 API 事实来源。

- 自动提取名称、类型、是否必填、默认值以及公开事件/插槽/方法签名；解析导入类型、泛型和组合类型。
- `withDefaults` 和运行时声明中的默认值需正确关联；不能把未明确的默认值猜成 false、空串或空数组。
- 人工维护中文用途、场景、示例说明和必要的参数解释；类型和 API 名称不由人工重复录入。
- 复杂类型可展开查看字段说明；类型信息不能以含义不明的 object/any 替代已公开的具体类型。
- 子组件分别显示自己的 API，不把父子组件属性混为一张表。
- 对无法可靠解析的公开契约列出需要人工确认的结构化覆盖项；构建报错要求补齐，不能静默遗漏。
- 每个公开运行时导出必须映射到文档页或文档区域；未记录导出、失效属性或错误必填性应使检查失败。

根目录的组件契约审计仍保留其组件库行为检查；将其对旧 `site/src/docs/api.generated.json` 的依赖改为新版生成契约。相关测试中的旧文件路径和旧 DOM 结构一并替换，不能直接删除校验来让构建通过。

## 8. 搜索、目录与交互

- 本地搜索索引覆盖组件中英文名、简介、场景标题和 API 名称，不接入外部搜索服务。
- 点击搜索框或 Ctrl/Cmd+K 打开搜索，支持键盘选择、Enter 跳转、Escape 关闭和焦点恢复。
- 搜索结果显示组件与目标章节，支持直接跳到示例或 API 锚点；空结果提示修改关键词。
- 右侧目录对应明确且稳定的标题 ID，随正文滚动更新，不通过持续遍历整页 DOM 维持状态。
- 左侧保留当前位置并确保当前条目可见；切换组件后正文回到顶部，通过锚点进入时定位目标。
- 移动导航与搜索具有焦点约束、遮罩关闭和 Escape 行为，不与组件示例中的浮层抢占交互。
- 主题通过全局 theme 统一控制，默认跟随系统并保存用户偏好；组件效果与文档配色同步，文档阅读尺寸不随全局 size 变化。

## 9. 旧站与开发记忆清理

审批通过后先删除旧站实现，再建立全新目录内容。删除对象包括旧页面、示例、样式、路由、脚本、测试、生成数据、静态资源及构建产物。依赖清单和配置也按新版需求重新生成，不沿用旧站特殊控制器。

记录清理范围：

- 旧站重建、旧 API 文档重建及 demo 重建的历史设计和实施计划。
- 旧站的审查报告、页面截图、浏览器证据和示例盘点。
- 本地旧站相关设计草稿、工作记录和缓存；混合记录移除旧站部分，保留独立的组件功能资料。
- 可访问的长期记忆中如存在对应条目，删除该站点条目；目前检索的长期记忆目录未发现 zt-ui site 专门条目。

处理边界：

- 保留组件库实现、公共类型和组件行为回归，以及当前有效的发布事实。
- 不将旧站布局、旧示例和旧设计要求重新导入为新版决策依据。
- 本设计及新版需要的技术文档属于当前资料，不保留对话内容或任务执行流水。
- Git 历史不做强制改写；其他功能分支和其他项目的记忆不删除。清理以当前工程和可访问的站点专属记录为范围，不能声称抹除不可访问的聊天历史或平台记忆。
- 当前演示端口 4185 在新版可用时切换到新站；删除旧站构建产物和已合并且不再使用的工作区中的旧站副本，避免继续展示旧页面。

## 10. 技术与发布

技术选择建议：Vue 3、TypeScript、Vite、Vue Router、SCSS，沿用项目 npm 工具链。文档壳使用简单语义 HTML 与专用站点样式，示例使用真实 Zt UI 组件。语法高亮使用本地打包依赖，不向外部服务发送源码。

建议的新站组织：

```text
site/
  src/
    app/                 路由、主题、导航与应用入口
    layouts/             文档布局
    components/          示例容器、API 表格、搜索和目录
    content/             指南、组件说明及文档归属清单
    examples/            按组件组织的新示例
    generated/           API 与搜索生成数据
    styles/              文档站令牌和响应式样式
  scripts/               新版生成、文档覆盖和示例校验
  tests/                 导航、交互、内容契约和生成器测试
```

- 指南与组件路由分别使用 `/guide/...`、`/components/...`。
- GitHub Pages 使用 `/zt-ui/` 基路径和 hash 路由，保证刷新、深链和资源地址正常。
- 已公开的旧组件地址映射到新组件页；只保留重定向数据，不保留旧页面代码。
- 更新中英文 README 中的文档入口，保持中文主 README 和现有精简形式。
- 调整现有 Pages 工作流中的依赖安装、验证和构建步骤，部署仍输出 `site/dist`。

## 11. 验收

### 内容和功能

- 公共导出清单全部有文档归属；无空组件页、无通用占位示例、无虚构 API。
- 所有示例都能渲染、实际操作、重置，并能复制完整代码。
- 全局 size、borderRadius 和 theme 跨页面、刷新和预览浮层保持一致，显式覆盖符合组件契约；外观切换不丢失示例业务状态。
- 示例中暴露的主要操作具有对应结果；复杂组件通过完整场景验证。
- API 名称、类型、默认值、必填性、事件与公开插槽/方法符合源码，遗漏和失效内容触发检查失败。
- 新版目录和脚本不导入旧站文件；旧站专属开发记录和生成产物清理完成。

### 自动检查

- 组件库完整回归、类型检查、ESM/UMD 与 Canvas 子入口构建、组件契约审计。
- 新站类型检查、内容/路由/API/示例覆盖检查、交互测试及生产构建。
- 示例源码编译检查，以及复制代码在独立 Vue 消费项目中的代表性验证。

### 浏览器检查

- 桌面约 1440px、平板约 1024px、移动约 390px，以及 320px 窄屏；明暗两种主题、五档尺寸及 0px/11px/24px 代表圆角。
- 全部文档路由能打开，示例无运行时异常；核心组件逐项完成关键交互。
