# Hierarchy implementation report

Implemented ZtTree, ZtTreeSelect, ZtCascader, ZtTransfer and Tree virtualization. Public types are exported from each feature index.ts. ZtTreeKey/Node/Fields/Loader/Props, ZtTreeSelectValue/Props, ZtCascaderPath/Value/Props, ZtTransferKey/Option/Props.

Tree and Cascader use a shared flattened hierarchy model with mapped fields, inherited disabled state, stable keys and full paths. TreeSelect reuses Tree and existing Popover. Cascader presents separate level columns. All entry controls use Form size/disabled/change/blur validation and ConfigProvider tokens. Popover supplies inherited themes, overlay branch registration, outside close, Escape and focus restoration. Tree supports virtual windows, filtering with ancestors, controlled expansion/check/selection, strict checks, partial state, lazy errors/retry, stale-response suppression, slots, and keyboard navigation. TreeSelect supports all/parent/leaf strategies, collapsed tags and clear. Transfer retains unknown controlled keys, respects disabled options, supports filtered select-all and direction/moved-key change events.

Source-matched demos: Tree Basic/Virtual/Lazy, TreeSelect Basic/Advanced, Cascader Basic/Advanced, Transfer Basic/Advanced. API reference is centrally rendered by site App. No shared exports/catalog/API files modified by this agent.

Controlled value semantics: Tree checked keys change only through emit; non-strict display normalizes descendants and ancestors. Single TreeSelect empty value null, multiple empty []; Cascader always full paths, clear []; strict Cascader allows branch paths, non-strict allows terminal paths; multiple paths remain independent. Disabled parent disables all descendants. Load callbacks return node arrays, rejected requests show retry; data replacement/unmount ignores old results. Virtual Tree defaults height=280,itemHeight=32; only expanded/filter-matched rows mount within window plus overscan.

Additional API integration: every public Props member now has precise Chinese JSDoc. Tree emits `check(keys,node)` after its controlled checkedKeys update event and includes the clicked raw node; `select(node)` follows selectedKeys update; `load-error(error,node)` reports rejected lazy load, leaving retry available. TreeSelect/Cascader `load-error(error,node)` has the same contract. Transfer `left-check-change(keys)` / `right-check-change(keys)` reports internal checkbox selections after individual/select-all/move-clear actions; it does not change target modelValue. All four now accept six-status `status?:ZtButtonStatus` (default primary) and actual semantic selected/check/focus colors. Tree row height follows size 24/28/32/36/40 unless itemHeight supplied.
